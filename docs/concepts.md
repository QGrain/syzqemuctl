# Concepts

## Image home

The image home is the configured parent directory for every managed image. The
CLI reads it from `~/.config/syzqemuctl/settings.json`; the Python API can also
construct an `ImageManager` directly from a path.

## Template and image

An **image** is a directory containing at least the guest disk and SSH key
material generated by Syzkaller:

```text
my-image/
├── bullseye.img
├── bullseye.id_rsa
├── bullseye.id_rsa.pub
└── .image_ready
```

`image-template` is the default source copied by `ImageManager.create()`.
Directories named `image-template-SIZE` are caches for custom disk sizes.

An image is persistent. Starting or stopping a VM does not normally delete the
image directory.

## VM runtime

A **VM** is the host runtime started from one image. `VM.start()` adds these
files to the image directory:

- `boot.sh`: the generated QEMU command and last boot configuration;
- `vm.pid`: QEMU's pidfile while runtime state exists;
- `vm.log`: serial console output written through `tee`.

The QEMU process runs in a path-specific `screen` session. The screen name is an
implementation detail; use `VM.screen_name`, `status`, or
`runtime_diagnostics()` instead of reconstructing it externally.

## Saved boot configuration

`boot.sh` records the kernel path, SSH port, memory, CPU count, and guest kernel
command line from the latest start. A later `start()` or CLI `restart` can reuse
that configuration.

Snapshot mode is intentionally not inherited. Pass `snapshot=True` or
`--snapshot` on every start where disk changes must be discarded.

## Ownership and locking

Runtime process matching requires a QEMU command line that references the exact
`bullseye.img` path. Start, stop, and delete operations are serialized with a
per-image host lock. Different images can still run in parallel.

Do not access private methods such as `_qemu_pids_for_image()` or the `_ssh`
attribute. Public lifecycle, I/O, cleanup, and diagnostics APIs provide the
supported integration surface.
